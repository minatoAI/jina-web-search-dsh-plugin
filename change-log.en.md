# Changelog

Full version history of dsh-jina; the "Changelog" section of [README.en.md](./README.en.md) keeps only the latest release.

### 0.12.1 (2026-09-24)

- **fix** **`jina_read` no longer hangs on the default selector group.** `X-Target-Selector` implies the server-side `X-Wait-For-Selector` (same value), so a selector that never appears keeps the Reader waiting until `X-Timeout` — which was 120 s, exactly the client's own ceiling. "The default selector list does not match this page" therefore surfaced as a **network timeout**. Measured: `POST r.jinaai.cn` with the selector group sat on a news page for more than 45 s, while the same page without the group answered in 30 s with 23625 characters; the 36kr page answered 422 in 1 s with the group. The selector attempt now runs with **`SELECTOR_WAIT_TIMEOUT_SECONDS` = 30** server-side and **`SELECTOR_ATTEMPT_TIMEOUT_MS` = 45 s** client-side, so the server always answers first (usually the 422 the fallback already handles) and the existing whole-page re-read runs; a selector-less read keeps `X-Timeout: 120` and the 120 s client budget. All three fallback shapes are now handled in one place — a short body, a 422 naming the selector, and the **new status 0** (the implied wait outlived the client ceiling) — instead of reporting the last one as a network failure. **Verified live** (fake host, real helper, proxy variables stripped, `endpoint: cn`): the 163.com page succeeded in 4.3 s and 36kr in 1.9 s, two attempts each (selector → whole page).
- **fix** **`targetSelector: ""` now really means "read the whole page".** The old `args.targetSelector || defaults.targetSelector || DEFAULT_TARGET_SELECTORS` let an empty string fall back to the built-in list, which made the `retry with targetSelector: ""` advice in the 422 hint a **no-op**. Only an *unset* argument falls back to the configured / built-in list now; an explicit empty string sends no `X-Target-Selector` (the `X-Remove-Selector` chrome stripping stays).
- **fix** **`jina_primer`'s network section is back (a 0.12.0 regression).** 0.12.0 made `jinaRequest` route everything through the endpoint table, so the `ipinfo.io` call landed on the Reader root and came back as usage text, `parseIpInfo` failed and `network` stayed `null` — silently, because the tool never throws by design. `jinaRequest` supports an **explicit absolute-URL escape hatch** again: only Jina hosts go through the endpoint table, an explicit URL is a single attempt that inherits the environment untouched and never touches `preferredSide` (a non-Jina host says nothing about which Jina side works). **Verified live**: `network` is a real public IP / city / ASN again.
- **test** Full suite: **155 tests (154 pass, 1 opt-in `JINA_LIVE_CN` skip, 0 fail)**. New: the selector attempt's `X-Timeout`/client ceiling against the whole-page read, an explicit empty `targetSelector` reading the whole page (including "exactly one request"), a selector attempt returning status 0 falling back to the whole page, a transport failure without a selector group naming the domain instead of retrying; plus the `jina_primer` ipinfo absolute-URL regression (asserting the helper receives `https://ipinfo.io/json` and its environment is untouched).

### 0.12.0 (2026-09-24)

- **feat** **New "endpoint" switch: mainland / global / auto — the plugin needs no proxy from now on.** The `jina-tools` namespace gains an `endpoint` field (`settings.js`'s `ENDPOINT_FIELD`), rendered on the card as a three-way select that **saves on selection** and takes effect on the next call: `cn` = Jina's official mainland mirrors `r.jinaai.cn` / `s.jinaai.cn`; `global` = `r.jina.ai` / `s.jina.ai`; `auto` (default) = **use whichever side answered last, and switch to the other when it fails**, with the winner remembered in-process (`preferredSide`), so only the first call may pay for one extra probe. The route plan comes from `settings.js`'s `routePlan(mode, kind, preferred)` — a fixed mode offers exactly one candidate (a failure is reported rather than papered over by the other side), while `auto` offers two and **never repeats a host**.
- **feat** **The mainland domains are vendor-provided and measured equivalent.** Per [jina-ai/reader#1237](https://github.com/jina-ai/reader/issues/1237): `jina.ai` has been DNS-poisoned in mainland China since 3/29, and the vendor offers `r.jina.ai → r.jinaai.cn` and `s.jina.ai → s.jinaai.cn` ("the API, parameters and authentication are identical, only the domain changes"). **Measured**: `r.jinaai.cn` resolves to 182.140.172.x / 220.167.110.x (response header `Server: ESA`, Alibaba Cloud edge), answers 200 on a **direct connection through no proxy**, and returns content **byte-for-byte identical** to `r.jina.ai` through a proxy (the same URL, 7521 characters, the same title), settling at 1.1–1.2 s (24.8 s on the first cold start while the CDN warms its origin); `r.jinaai.cn` with an API key returns `authenticatedAs`, and the `s.jinaai.cn` search endpoint with a key returns 200 (15.4 s cold, 1.7 s afterwards).
- **change** **Five tools removed**: `jina_embed` / `jina_rerank` / `jina_classify` (all hitting `api.jina.ai`, which has **no mainland domain**: `api.jinaai.cn` → HTTP 525, and the domain is blocked by SNI — the same Cloudflare IP answers 301 normally with SNI `cloudflare.com` and resets immediately with SNI `api.jina.ai`, so the `hosts`-pinning workaround the community suggested in that issue no longer works), `jina_expand` (`s.jina.ai` does not support `query_expansion`; measured, it degrades into an ordinary search), `jina_pdf` (`extract-pdf` exists only on `svip.jina.ai` and has no mainland mirror: `s.jinaai.cn/extract-pdf` is not that endpoint and returned unrelated page content). **The basis is real usage**: unpacking 21 days and 557 session logs (multi-frame zstd JSONL) and counting call records by tool name, those five tools totalled just 21 records (~10 calls), against 2570 for `jina_read` and 1620 for `jina_web_search`. Those capabilities will continue to be maintained in a separate repository.
- **change** **The entire proxy mechanism is deleted.** `proxy.js` (proxy-address normalization / the precedence request > setting > `JINA_PROXY_URL` > WinINET > inherited environment, `describeRejectReason`, `selectProxy`) is removed outright and replaced by `settings.js` (settings + endpoint policy); also gone are the card's "local proxy" input and its save/clear logic, the `JINA_PROXY_URL` environment variable, the `reg.exe` WinINET registry probe, the proxy-source hint in error messages, the `proxy` / `proxyConfigured` fields of `/api/dsh-jina/primer`, the `proxy` result field `withProxy` attached, and `test/proxy.test.js` with `test/plugin-proxy.test.js`. A mainland-domain attempt now **appends** `jinaai.cn` to `NO_PROXY` through `cnBypassEnv()` (keeping the inherited list, writing no `HTTP_PROXY`), so a startup environment carrying a proxy cannot push a domestic CDN address into the VPN — verified with a "fake proxy (accepts connections, never answers) + `NO_PROXY`": with `NO_PROXY` → 200 in 0.7 s, without it → hangs until the timeout.
- **change** **The search endpoint moved from `svip.jina.ai` to `s.jina.ai`** (mainland mirror `s.jinaai.cn`). This is the officially documented endpoint and both sides return the same shape `{ code, status, data: [{ title, url, description, date }] }`, so one `fmtSearch` covers both routes (it still tolerates the old `{ results: [...] }` shape and reads `description` and `date`). Measured: the `domain` field has **no effect** on `s.jina.ai` (it returned distill.pub results, where `svip` honoured it), so the arxiv / ssrn academic tools now use the measured-working `site` field (`site: 'arxiv.org'` / `site: 'ssrn.com'`).
- **fix** **A transport failure no longer retries the same host.** The old `jinaRequest` retried in place once on `status === 0`, which with `jina_read`'s 120 s ceiling could take **240 s** to report an error (measured: a failed `jina_read` spawns two helpers, both with `timeoutMs` 120000). A failure is now a **routing fact**: `auto` moves to the other side, tries each host once and makes at most two attempts per call; the fixed `cn` / `global` modes error on the first failure. The error text now names **the endpoint URLs actually tried** (e.g. "endpoints tried: https://r.jina.ai/, https://r.jinaai.cn/"), and a fixed `cn` mode also suggests switching back to "auto" or "global".
- **test** Full suite: **150 tests (149 pass, 1 opt-in `JINA_LIVE_CN` skip, 0 fail)**. New `test/settings.test.js` (endpoint-policy pure functions: mode validation and defaults, a single candidate in a fixed mode, `auto`'s order and winner memory, at most two attempts per combination without repeating a host, `NO_PROXY` merging and deduplication) and `test/plugin-endpoints.test.js` (fake-host integration: the global side with **a fully inherited environment** when nothing is configured, a transport failure switching to the mainland side and appending `NO_PROXY`, winner memory, a non-transport failure also pinning that side, no fallback in a fixed mode, the error text listing the domains tried, search using the search domain pair, the `site` field, saves taking effect immediately, and the primer reporting the endpoint side actually used). Its `JINA_LIVE_CN=1` case really spawns the helper and completes one mainland-domain request (**verified, 824 ms**). `test/proxy.test.js` and `test/plugin-proxy.test.js` were deleted, and `multi-key.test.js` (a transport failure now switching the endpoint domain instead of retrying), `reader-headers.test.js` (`proxyUrl` → `endpoint`, the six `jina_pdf` cases removed), `tool-args.test.js` (the guard cases for the removed tools removed), `client-bundle.test.js` and `client-render.test.js` (the proxy input → an endpoint dropdown, asserting the options are exactly auto/global/cn) were rewritten to match.

### 0.11.0 (2026-09-24)

- **feat** **`jina_pdf` now returns the extracted figures/tables as images.** The raw payload showed that `extract-pdf` answers each detected "float" (LaTeX's word for figures/tables/equations) with only `type / number / page / caption / image(base64 PNG) / width / height` — **no text field at all** (`text`/`markdown`/`latex` never appear), and the caption is the constant placeholder `"Table (detected)"`. The image *is* the payload, so the old formatter printing only an inventory and dropping 1.2 MB of images left the tool effectively useless. Now: base64 → `Uint8Array` → `ctx.attachments.saveImage()` → `{ type: 'image', attachment }` content blocks (the same contract the built-in `read_image` uses), so **the model can actually look at them**. The inventory stays (with per-item pixel sizes, and unattached items marked), `maxImages` bounds how many ride along (default 5, also clamped by `attachments.imageLimits.maxImagesPerMessage`), and a crop the store refuses (too large, wrong media type, no attachments service) is reported in `[Notes]` instead of losing the whole extraction. **Verified live**: 11 tables from arXiv `2601.21337`; the first two decode to `137,80,78,71,13,10,26,10` (the PNG magic number) at 77,173 / 116,983 bytes.
- **change** **ReaderLM-v2 removed** (the card option `useReaderLm`, the `readerlm` parameter, and its code/tests/docs). Every reason came from measurement: (1) on ordinary pages it tied the plain extractor (example.com, arXiv — identical content), with no evidence of an advantage; (2) it cannot carry the selector group (doing so answers 422 `No content available`), so it reads the whole page with all the chrome; (3) the vendor positions it as "you already have the HTML → markdown/JSON", and the one irreplaceable capability (HTML→JSON) has no use here; (4) on the long, formula-heavy page it was supposed to excel at (Wikipedia "Normal distribution") it failed — the output contained **raw HTML** (`<b id="mwKg">`, i.e. it echoed its input) and blew past the plugin's 1.5 MB transport cap. A related piece of official-doc staleness: the model card says to reach Reader through `x-engine: readerlm-v2`, but that header **does nothing** on the live API (1x billing, plain-extractor-shaped output) — only `X-Respond-With` really engages the model, which is what the plugin already used. `jina_read` is now plain-extraction only; OCR still lives solely in `jina_read_pdf`.
- **fix** **A truncated response is no longer misreported**: `parse()` now checks the helper's `lossy` flag and, past the 1.5 MB cap, says the response exceeded the transport cap, names the spilled body, and suggests narrowing the request. The old code ignored `lossy`/`spillPath` and handed the truncated slice to `JSON.parse`, reporting `helper output not parseable` next to a garbled snippet.
- **change** **`jina_pdf` now asks whether the current model can see images**: it applies the harness's own gate (the same route resolution and `inputModalities` check `read_image` uses) — a **resolved** text-only route gets no attachments, with the reason in `[Notes]` (attaching would only fill durable history with blocks the harness replaces by a placeholder on every request); an **unresolvable** route still attaches, because the harness projects images to text itself and the plugin must not drop them on its behalf.
- **test** Full suite: **171 tests (170 pass, 1 opt-in `JINA_LIVE_PROXY` skip, 0 fail)**, with six new `jina_pdf` cases (image blocks with attachment names/bytes, the no-attachment-store fallback, the `maxImages` cap, one refused crop not losing the extraction, a text-only route storing nothing, and an unresolvable route still attaching); `jina_read` is now asserted to never send `X-Respond-With`; the card's checkbox count dropped from three to two.

### 0.10.0 (2026-09-24)

- **feat** **New `jina_read_pdf`: `jina-ocr-v1` now lives in a PDF-only tool.** A measured incident drove this. `jina-ocr-v1` consumes **one page image** per call, while the Reader renders a whole web page into **one** image before handing it over — so a long HTML page is crushed into the 1024x1024 global view until the text is unreadable, and the model *invents* what it cannot read. The same arXiv paper came back as a fabricated "genetic-algorithm test-case generation" paper via HTML (`inputTokens=957, outputTokens=1367, measuredTokens=2324, scaledTokens=92960`, byte-identical on three separate calls) and completely correct via the PDF, page by page. OCR is therefore no longer a global switch: `jina_read_pdf` always sends `X-Respond-With: jina-ocr-v1`, requests **one page at a time** (`X-Page`, 1-indexed), defaults to the first 5 pages (`maxPages`, hard cap 50), and accepts `pages` as `"3"` / `"1-5"` / `"2,4,7"`.
- **feat** **End-of-document detection.** Measured: an out-of-range `X-Page` does **not** error — the API silently serves page 1 again, so a "loop until empty" would never terminate. The tool fingerprints each page's content and stops when a page repeats an earlier one, saying so in the result.
- **feat** **Results carry a provenance marker.** Both model pipelines (`jina-ocr-v1`, `readerlm-v2`) *generate* text instead of extracting it, so a result ends with `[Reader pipeline: … — … verify anything load-bearing against the source.]`. It is the cheapest guard available: the model reading it can choose to verify instead of quoting it as fact.
- **feat** **The `X-Respond-With` default moved from OCR to ReaderLM-v2.** The card field `useOcr` became **`useReaderLm`** ("read HTML through ReaderLM-v2"), using the `X-Respond-With: readerlm-v2` the vendor documents for **web pages**. Measured on the page OCR fabricated: ReaderLM-v2 returned the **correct full text** at **3x** the tokens with a 4000-token minimum, versus OCR's 40x. A stale `useOcr` key in settings is ignored rather than an error.
- **fix** **ReaderLM-v2 no longer carries the selector group.** Measured: `X-Respond-With: readerlm-v2` **plus** `X-Target-Selector` answers **422 `No content available`** as soon as the selector matches nothing (which is every page the default list does not fit); dropping the group restores the read. A model pipeline consumes the whole page, so the selectors — and the "empty result" retry built on them — are dropped in that mode.
- **fix** **A `.pdf` URL is never taken over by ReaderLM.** `jina_read` keeps the plain extractor for PDFs (verbatim, and ~40x cheaper than OCR) and states in the result that ReaderLM did not apply and that `jina_read_pdf` is the tool for a scan without a text layer. ReaderLM-v2 converts HTML; a PDF is not its input.
- **fix** **422 is routed by its message.** `Screenshot of the page is not available` means the page could not be **rendered** — exactly the step behind OCR fabrication, and the same failure that sometimes returns HTTP 200 with invented text instead; `with target selector …` means the selector matched nothing; `No content available` means nothing was extracted. Each gets its own repair hint, and the plugin now also retries once without the selector group when the 422 names it (the old retry was gated on `res.ok`, so a selector-driven 422 never retried). 503 now carries the vendor's guidance: the model is serverless, **a cold start answers 503, and the vendor says to retry after 30-60 seconds**.
- **change** **The key pool rotates round-robin.** The old policy was sticky (the key that served the last success led every following call); now each call starts at the key **after** the one used last, so N keys share roughly 1/N of the traffic. Jina's limits (RPM/TPM) are per key, so spreading is what keeps a busy session out of 429. Keys in cooldown are still skipped, and **only a real failure prints `[已自动切换 API key: …]`** — a planned rotation must never look like "your key ran out".
- **change** **`jina_pdf` now asks whether the current model can see images**: it applies the harness's own gate (the same route resolution and `inputModalities` check `read_image` uses) — a **resolved** text-only route gets no attachments, with the reason in `[Notes]` (attaching would only fill durable history with blocks the harness replaces by a placeholder on every request); an **unresolvable** route still attaches, because the harness projects images to text itself and the plugin must not drop them on its behalf.
- **test** Full suite: **171 tests (170 pass, 1 opt-in `JINA_LIVE_PROXY` skip, 0 fail)**. Added/rewritten: `jina_read_pdf`'s per-page requests, the repeat-page stop, the non-PDF guard, the `allowNonPdf` escape hatch, the key-gated refusal, and the provenance marker; `jina_read`'s ReaderLM headers, the PDF carve-out, and the dropped selector group; `keys.test.js`'s round-robin order; `multi-key.test.js`'s consecutive-call rotation. Also **verified live end-to-end** (real API, real subprocess seam): `jina_read_pdf` asked for pages 1-3 of a one-page PDF reads page 1 only, stops with "page 2 repeated page 1 (past the end of the document)", and marks its provenance; `jina_read` with `readerlm` returns correctly.

### 0.9.0 (2026-09-24)

- **feat** **Multiple API keys with automatic rotation and automatic discard.** A Jina account whose credits run out answers HTTP 402, and before this release that ended the operation: the task was interrupted mid-flight and the user had to notice, top up and start over. The card now has **one key input**: paste a key and click 添加, and you can keep adding — no individual key ever needs managing. The host resolves the stored keys into a **rotation pool**, and a key that answers **401 / 402** is parked and the next key serves the call, so the operation completes. The credential seam stores one value per reference and its `describe` view carries `configured`/`source`/`writable` only (no read path ever returns a value, so the card cannot read the list back and "append" can only mean "write the first free slot"), so "several keys" is "several references"; the reference grammar is a plain POSIX identifier, verified against `packages/credentials/credentials/src/index.ts:19` and the Remote controller `packages/api/settings-controller/src/credentials.ts:22-27` (`.max(64)` per describe batch), so **no harness change was needed**.
- **feat** **A key that cannot be used is discarded automatically.** 401, 402, and a key the health check finds with a **balance of zero or less** are deleted from the credential store by the host half via `credentials.unset`, so the pool cleans itself — which is why the card has **no remove control and shows nothing per key** (no plaintext, no fingerprint, no "which one is in use"). A rate limit (429) only parks the key for one minute; network/argument/upstream faults neither rotate nor discard. A reference shadowed read-only by the launching environment (the seam refuses the write) and a key from `jina-api-key.txt` (the plugin will not rewrite a user's file) are only skipped, never deleted.
- **feat** **New pure module `keys.js`** owning the pool policy so all of it is unit-testable without a harness: `KEY_REFS` (the slot table), `parseKeyList` (one key per line, blank lines and `#` comments ignored, duplicates collapsed), `KEY_FAILOVER_STATUSES` / `isKeyFailoverStatus` (only 401/402/429 — `0`/`422`/`5xx` are not key problems and rotating would waste the pool), `KEY_BLOCK_MS` (401 → 30 min, 402 → 5 min, 429 → 1 min; the fallback when a discard cannot happen), `keyStateAfter` / `isKeyBlocked` (success clears a key, a non-failover status never parks one), `keyRotationOrder` (sticky first, parked keys demoted, and a fully parked pool is still walked in order — an honest failure beats refusing to call the API), `keyPoolSignature` (a djb2 hash, never the values, so the rotation state is not a second place secrets live), `keyStatusOf` / `describeKeyStatus` and `keySourceLabel`.
- **feat** **The key file may hold several keys.** `jina-api-key.txt` is now one key per line (blank lines and `#` comments ignored, duplicates collapsed); the historical single-line file still yields exactly one key, and a credential slot whose value holds several lines is split the same way. Source precedence is unchanged — `apiKey` parameter (a single key, never rotated), credential slots in add order, workspace key file, dsh-home key file — and the **first source that yields a key is the pool**, so a credential user never pays for the file probe. Every source is re-resolved per operation (the seam's contract) and a changed pool resets the cooldowns and the cursor.
- **feat** **The page reports the key count and one total.** `/api/dsh-jina/primer` probes every key in parallel (one request per key, no rotation — deciding whether a key can serve a call requires validating each one) and returns only three numbers: **how many it holds** (`keyCount`), **the total balance** (`balanceTotal`, the credits behind the surviving keys; `null` when none reported one, so the page says "unknown"), and **how many were discarded by this check** (`discardedCount`) — **nothing per key**, and no usable/total fraction (`keys[]`, `usableCount`, fingerprints, `activeKey`, individual balances and identity are all gone from the payload). The probe also cleans up dead keys and folds its result into the rotation state, so **a rate-limited key returns after a Refresh** with no restart. `ok` / `authenticatedAs` / `balanceLeft` still come from the first working key, and are used for the connection state only — the page shows neither identity nor any per-key balance.
- **change** **The failover is visible.** A successful call that switched keys carries `res.keySwitch` and each tool appends one `[已自动切换 API key: …]` line to its formatted result — `withKeyNote(text, res, asJson)` never touches a `json: true` payload, because a note appended to JSON would no longer parse. A key that was actually deleted is marked `已自动移除` in that line (a failed delete is never claimed as one). When the whole pool fails, `describeJinaError` appends `API key 轮换：已依次尝试 N 个 key —— …` and points at adding a key or topping up; the fatal-status routing of 0.8.2 is unchanged (a 401 pool throws, a 402/429 pool returns its hint). The key-lookup diagnosis became compact (`credential slots: none of 10 set`) so ten unset slots cannot drown the error.
- **change** `loadKeyPool()` replaces the single-key `loadKey()` (which remains a thin "is any key configured" wrapper for the OCR gate); the dead `credentialKey()` helper and the now-unused `maskKey()` were removed. The pool walk re-reads the sources once after the whole pool answers a failover status — the generalisation of the old 401 re-read, so a credential or key file fixed mid-call is picked up — and dedupes by value so a key stored twice is requested once.
- **test** New `test/keys.test.js` (9 cases: every slot satisfies the Remote reference grammar, the slot count, file parsing, status mapping, cooldown folding and expiry, rotation order including the all-parked and out-of-range cases, pool signature stability and change, source labels) and `test/multi-key.test.js` (28 cases against a fake Cordis context whose helper stdin is decoded per request: a 402 handing over to slot 2 **and deleting it from the credential store**, 401 doing the same, 429 only parking, read-only and file-sourced keys never deleted, the sticky key leading the next call while the parked key is skipped, a three-key 402→429→200 walk, 422/503/status-0 stopping the rotation, an explicit `apiKey` never rotating, a fully exhausted pool naming every key, a revoked pool throwing with the same account, the file fallback with several lines, the first-source-wins precedence, a multi-line credential slot, duplicate collapsing, an added key reaching the next call, the anonymous path, the needs-key message, the OCR gate seeing slot 2, a primer route that returns only counts and the total, a zero-balance key being discarded, a rate-limited key surviving and recovering on the next probe, and an empty pool). `client-render.test.js` asserts **exactly one key input**, that **nothing per key is rendered** (no list, no remove control, no identity, no per-key balance), the add control closing when every slot is filled, and the health section showing "可用 Key：N 个" + "Key 总数：M 个" + "总余额" with **no fraction** (its stub now runs the effect and provides a `fetch`, so `describe(KEY_REFS)` is observable); `client-bundle.test.js` pins the slot table against `keys.js`, the single-input form (`keyDraft` string + `firstFreeRef` + add, and the card itself never calls `unset`), and the unchanged single settings write path. Full suite: **160 tests, 159 pass, 1 skipped (`JINA_LIVE_PROXY`, opt-in), 0 fail**.
- **verify** Cross-checked the seam contract against the harness checkout: `credentials.describe(refs)` returns `Record<string, CredentialInfo>` with no value slot and no reference enumeration, `set(ref, value)` rejects an empty value and accepts any non-empty string, and `unset` throws for a reference the launching environment shadows (swallowed by `discardKey`, which falls back to the cooldown machinery); refusals arrive as `RemoteError('credential/rejected', …)` whose message the card shows verbatim. `ui/client.js`'s `KEY_REFS` is pinned equal to `keys.js`'s by a test, because the credentials namespace has no enumeration and the card can only describe names it writes down — which is also why "append" had to become "write the first free slot".

### 0.8.2 (2026-09-23)

- **fix** **Closed the last two inconsistencies in error propagation** (0.8.0 recorded them as "not changed for now"): the URL check in `jina_read` / `jina_screenshot` / `jina_datetime` used to **return a string** — `'invalid url: undefined (must start with http:// or https://)'` — measured as **`isError: false`**, so the model could read that message as data. The root cause is that the line was a **local regex pre-check** sitting before `callJina` and **never sent a network request**, so it had nothing to do with an upstream status code. It is now `requireUrlArg()` (a line-by-line copy of `requireStringArg`'s contract and message format, reusing `argAt` / `argsReceived`) and it **throws**; the check also moved above `enterExec` to match `runSearch`'s "validate before any side effect", and it is still zero requests. This also fixes the diagnostic defect where `'invalid url: ' + args.url` printed `[object Object]` for an object — the message now reports `(number) 42` / `(string) "example.com"` and adds `did you mean "url" instead of "uri"?` for a likely typo (the alias list `['uri','link','href']` is only used for the hint, never for the value, matching `requireStringArg`'s `['queries','q']`).
- **fix** The **OCR-without-a-key** path in `jina_read` likewise changed from "return a string" to **throw** (wording unchanged). 0.8.0 described it as "returns an actionable message", but it is a **pre-emptive refusal**, not an API response, and a returned value lets the model treat it as a result; throwing makes the harness mark `isError: true` while keeping the "no key detected, no request sent" promise.
- **change** **Upstream errors are now routed by status code**: new `failJina(res)` plus `FATAL_JINA_STATUSES = {401, 422}` — `401` (invalid/missing key) and `422` (illegal arguments) **throw**, because the model has to change its key or its arguments; `0` (network/proxy), `402` (quota), `429` (rate limit) and `5xx` **stay returned**, because their hint exists to be relayed to the user or retried later and must not push the model into "fixing" its own arguments. All nine `if (!res.ok) return describeJinaError(res)` sites became `return failJina(res)` (the `runSearch` one is indented four spaces and was checked individually). **`jina_primer` (`error: describeJinaError(out)`) is deliberately untouched** — it assembles a JSON payload and its tool description promises "the tool never throws". `callJina`'s 401 refresh-and-retry runs before the status decision, so the "successful after a key rotation" path is not affected.

### 0.8.0 (2026-09-18)

- **feat** **`jina_read` gains an OCR switch (jina-ocr-v1)**: with `ocr: true` (or the card default) reads go through `X-Respond-With: jina-ocr-v1` — the vendor's 3.4B document parser, which turns a scanned page, image-heavy PDF or formula/table-heavy document into Markdown in one pass (tables as HTML, formulas as LaTeX), in English and Chinese. Multi-page documents can be steered with the `page` parameter (`X-Page`). The model costs roughly **40x the tokens**, and the **Reader rejects it for anonymous callers** (measured: `Authentication is required to use this feature (Vision Language Model / OCR)`), so the plugin **sends no request** when it cannot resolve a key and returns an actionable message instead.
- **feat** **Three zero-side-effect parameters on every read**, each verified against the official OpenAPI document and parameter panel: `X-Preset: agent` (the vendor's preset for AI agents — the docs state a preset **only fills options the caller did not set explicitly**, so it can never override an explicit parameter), `X-Base: final` (resolve relative links against the post-redirect URL), `X-Timeout: 120` (matched to the client's own 120 s ceiling — sending the documented maximum of 180 would be pointless, since the client gives up first and reports its own timeout; raise both together or neither).
- **feat** **Selector group on by default, with an automatic fallback**: reads now send a conservative `X-Target-Selector` (article containers only) and `X-Remove-Selector` (header/footer/nav/cookie banners/ads/sidebars/comments), plus new per-call parameters `targetSelector`, `waitForSelector`, `removeSelector` and `noCache`. `X-Target-Selector` **implies** a matching `X-Wait-For-Selector` and returns an empty page when nothing matches — so a first result shorter than 200 characters is **retried without the selector group**, keeping whichever body is longer (`SELECTOR_RETRY_MIN_CHARS`). The remove list deliberately omits `.modal` / `.popup` / `.overlay`, which can be the content container in an SPA.
- **feat** **Configurable image policy**: `X-Retain-Images` is no longer hardcoded to `none`; it defaults to the API default `all` (with `alt` / `none` selectable). The `images` / `links` parameters still append the image/link summaries.

Every field lives in the same `jina-tools` namespace and rides the **same revision-fenced write path** (`mutate(NS, ops, proxyView.revision)`), so the two blocks cannot clobber each other.
- **fix** **`X-With-Generated-Alt` now defaults to off**: it is a paid feature (anonymous callers get the same 401: `Authentication is required to use this feature (Alt text generation)`) and is **mutually exclusive with `X-Respond-With`** (the docs state alt generation does not work when `X-Respond-With` is set). - **fix** **`createSettingsSchema()` used to keep only `proxyUrl`**, so a newly added field was silently dropped and could never be saved. - **fix** **A required argument is no longer silently coerced into the string `"undefined"`** (defect found in a real session): `ctx.tools.register` hands `parameters` to the model API but **never validates at runtime** (validation lives only on the first-party `defineTool` path), so a key the model got wrong reaches the executor untouched. `String(args.query)` then turned a missing `query` into the four-character search term `undefined`, and Jina answered with MDN's `undefined` page — a **well-formed, `isError: false`** result that reads exactly like a real search. The check runs before `enterExec` and `callJina`, so **no request is spent**. Known remaining inconsistency: the URL checks in `jina_read` / `jina_screenshot` / `jina_datetime` still return a string; they cannot produce a plausible-looking fake result, so they were left alone.
- **change** `jina_read` now always asks for `Accept: application/json` and unwraps the envelope into markdown: a `Title` / `URL Source` / `Published Time` header plus a `[Usage: ...]` footer, with an unparsable body returned verbatim rather than dropped.
